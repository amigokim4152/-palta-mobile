# Secondary Surfaces — Minimum Contract
Version: v1.2

These surfaces are intentionally defined only to the depth needed to prevent architectural drift.
Do not overbuild them before Home → Neighborhood → Business → Care works end to end.

## Community

Purpose:
**"Where do I belong, and what is happening in those groups?"**

First-level sections:
- My groups
- Neighborhood
- School / church / organization when membership exists

Rules:
- trust scope is explicit but quiet
- private membership does not become public profile data
- same user identity, media, notification, moderation and permission cores
- posting is contextual
- no public feed forced into Home

Core states:
- public_local
- verified_local
- member_group
- private_relation

## Market

Purpose:
**"What can I find, offer, buy, sell, rent, apply for, or respond to?"**

First-level verticals:
- Secondhand
- Vehicles
- Property
- Jobs & Services

Rules:
- Browse remains visible.
- Create/Post is contextual inside each vertical.
- Each vertical can define filters and card grammar.
- Identity, trust, location, media, messaging and canonical data remain shared.
- Property and Vehicles may use Map Core; Secondhand may not need map-first UX.

## Play

Purpose:
**"What can I do with my time?"**

First-level:
- Eat & drink
- Events / culture
- Family activities
- Travel / stays

Rules:
- no endless lifestyle feed
- current location and saved context matter
- confirmed/planned travel can create a temporary Context Space
- travel does not add permanent navigation

## Build order

1. Home
2. Neighborhood
3. Business/Place detail
4. Care return
5. Market vertical shell
6. Community trust shell
7. Play discovery shell
8. deeper domain features only when the shared cores are stable
