# Palta Service Exchange & Partner Model v1

## Core thesis

Palta should connect a person's real-life need to:

1. understandable information
2. relevant entitlement/benefit
3. the right service category
4. qualified providers
5. quote / booking / action
6. payment when appropriate
7. status and follow-up

Palta does not need full direct integration on day one.

The progression is:

**Information → Understanding → Personalization → Action → Connection → Transaction**

## Service Exchange

Service categories are canonical and shared across verticals.

Examples:
- vehicle repair
- locksmith
- towing
- home repair
- education/tutoring
- insurance services
- pet services
- health-adjacent services where appropriate
- administrative/legal-support categories where permitted

A Life Event or direct user request may create a `QuoteRequest`.

Palta routes that request to a bounded number of relevant providers.

## Fair competition

Organic quote routing is not pay-to-win.

Provider routing may consider:
- service category match
- service area
- verification
- distance
- availability
- response quality
- recent exposure rotation

Paid promotion may exist, but must:
- be clearly labeled
- live outside the organic quote pool
- never silently replace organic ranking

This preserves user trust and creates room for healthy provider competition.

## Revenue paths

Possible Palta revenue mechanisms:

- merchant subscription
- transaction fee
- booking fee
- lead fee
- sponsored placement
- partner revenue share

Commercial compensation must not secretly distort organic service routing.

## Partner progression

Partners can connect progressively:

### 1. Information only
Palta structures public information.

### 2. Deep link
Palta sends the user to the partner's official action surface.

### 3. Structured exchange
Documents/status/quote information can be exchanged.

### 4. Transactional API
Palta can initiate supported actions inside the Palta flow.

The same Partner Core supports:
- insurers
- schools
- municipalities
- hospitals/clinics
- transport operators
- banks
- service providers
- commerce partners

## Business principle

Palta earns revenue by reducing friction and creating successful, useful transactions — not by making information harder to access.
